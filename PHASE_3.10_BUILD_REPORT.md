Implemented:
- SemanticRole vocabulary: background, foreground, container, group, text, heading, button, icon, logo, image, illustration, decorative, shape, unknown — controlled vocabulary extensible /^[a-z_][a-z0-9_]*$/ — MVP no large ontology
- SemanticSource: user, ai, heuristic, import, system — meaning user explicitly assigned, ai generated by AI reasoning, heuristic deterministic local inference, import from imported data, system internally assigned
- SemanticRelationship: targetObjectId ObjectID, type contains|containedBy|labels|associatedWith|decorates|references — references valid ObjectIDs, MUST NOT create second hierarchy, SceneGraph remains canonical owner, relationships meaning-level metadata only
- SemanticData: objectId ObjectID, role? SemanticRole, tags string[] normalized lowercase deterministic alphabetical unique, confidence 0..1 finite not NaN/Infinity, source SemanticSource, relationships SemanticRelationship[], updatedAt? — Single canonical representation ObjectID is key, no independent SemanticID
- SemanticStore: Map<ObjectID, SemanticData> canonical, methods get, has, set, delete, clear, getAll sorted by objectId deterministic, getByRole, getByTag normalized lowercase — canonical but MUST NOT expose uncontrolled mutation to AI/DSL/Renderer/Critic/Planner/tools, mutation via Transaction/Command
- Validation: ObjectID valid UUID, Confidence 0<=confidence<=1 reject NaN/Infinity/negative/>1, Tags strings deterministic normalized consistently avoid duplicate tags example ["ui","button","primary","interactive"] must not become ["button","button","BUTTON"] — normalization convention trim lowercase collapse whitespace alphabetical sort unique — invalid role, duplicate tags, invalid relationship, missing target ObjectID
- Object existence validation: semantic.objectId -> ObjectStore exists? If not VALIDATION_SCHEMA — No phantom semantic objects
- Stale semantic data: When Object deleted its semantic record MUST NOT remain orphaned — Transaction responsible for deleting object must remove/invalidate semantic metadata — When object recreated new stable ObjectID per ID contract never reuse semantic state merely because geometry looks identical
- Heuristic semantic inference: deterministic rule-based inference NOT LLM NOT ML — Input SemanticInferenceInput {objectId, geometry, appearance, sceneContext {parentId, childCount, siblingCount, depth, bbox {minX minY maxX maxY width height area}, isText, textContent}} — Signals geometry_type, aspect_ratio, size, position, appearance, text, scene_structure, relationship — Geometry rectangle ellipse path line dimensions aspect ratio area position, Appearance fill stroke opacity color similarity, SceneGraph parent/child relationships number children nesting ordering, Text text heading label proposed based on deterministic rules
- DO NOT OVER-INFER: conservative, insufficient evidence -> role unknown or no role proposal, do NOT invent semantic meaning, red rectangle alone NOT automatically button unless sufficient evidence, prefer unknown + tags + confidence over unsupported classification
- Semantic Proposal: SemanticProposal {proposalId unique, objectId, proposedRole?, proposedTags, proposedRelationships, confidence, evidence SemanticEvidence[], source heuristic|ai, createdAt?} — Proposal IDs unique via randomUUID but role/tags/confidence/evidence deterministic
- Evidence model: SemanticEvidence {signal geometry_type|aspect_ratio|size|position|appearance|text|scene_structure|relationship, description, weight} example role text confidence 0.92 evidence geometry_type -> text object text -> short content — exact confidence calculation deterministic no random
- Inference is Read-Only HARD RULE: SceneGraph GeometryStore ObjectStore AppearanceStore ConstraintStore -> Semantic Heuristic Engine -> SemanticProposal — No mutation occurs — inferSemantic MUST NOT semanticStore.set/delete objectStore.write geometryStore.write sceneGraph.write constraintStore.write — logically Read State -> Proposal
- Persistence flow: Inference -> SemanticProposal -> Validation -> User/AI approval -> create/update semantic Command -> Transaction -> Working Copy -> Validate -> Commit -> semanticStore -> SemanticUpdated Event — NO shortcut
- Command contract: create_semantic, update_semantic, delete_semantic deterministic reversible inverseCommand snapshot not required — inputs CreateSemanticInput UpdateSemanticInput DeleteSemanticInput — Commands deterministic reversible
- Undo/Redo: semantic mutations participate in existing History linear example create semantic -> Transaction -> Undo -> removed -> Redo -> restored — semantic inference itself has no undo because does not mutate state
- Events: SemanticCreated, SemanticUpdated, SemanticDeleted, SemanticInferred — inference produces proposal SemanticInferred, persistence produces Created/Updated/Deleted — Do NOT emit mutation events before Transaction commit — ordering Command -> Working Copy -> Validate -> Commit -> Diff -> Event -> Derived Invalidation -> Render
- Semantic Inferred Event: SemanticInferred MUST NOT imply persisted — payload proposalId objectId proposal source heuristic|ai — No mutation implied
- Semantic Query API: findObjectsByRole, findObjectsByTag, getSemantic, getSemanticConfidence, getRelationships — queries MUST NOT mutate state
- SceneGraph boundary: Semantic Engine MAY READ SceneGraph, MUST NOT become owner of hierarchy — correct SceneGraph parent children ordering, Semantic meaning role tags relationships confidence — never duplicate parent children z-order localTransform worldTransform inside SemanticData
- Geometry boundary: may read geometry MUST NOT modify geometry — Rectangle -> possible shape, TextObject -> possible text, Wide rectangle -> possible background candidate — proposals only
- Appearance boundary: may inspect Appearance MUST NOT modify fill stroke opacity appearance stack — cannot silently change appearance
- Constraint boundary: may read constraints example centered+repeated+same dimensions may provide evidence for semantic grouping but MUST NOT create constraints — if constraint needed Semantic Proposal -> separate Constraint Proposal
- AI boundary: AI can request infer semantic receives SemanticProposal cannot call semanticStore.set() directly — correct AI -> ExpectedState -> Plan -> DSL -> Tool -> Validation -> Transaction -> SemanticStore
- Critic boundary: Critic remains ReadOnly may inspect Expected semantic state Actual semantic state and produce Semantic deviation Correction proposal Critic MUST NOT modify SemanticStore
- Serialization: deterministic stable ordering valid ObjectIDs no runtime-only fields no circular compatible with future schema evolution — tags deterministic alphabetical, relationships deterministic sorted targetObjectId+type
- Import/Export: Do NOT redesign SVG import/export — if semantic not representable in supported SVG subset do not silently inject unsupported SVG structures — semantic remains internal unless existing import/export contract explicitly supports it
- Determinism: same document state MUST produce same semantic proposal — same geometry same appearance same scene structure must produce identical role tags confidence evidence across repeated executions — No Math.random Date.now unstable iteration inside deterministic inference logic (proposalId uniqueness除外)
- Confidence model: base confidence + evidence weights -> clamp [0,1] — transparent deterministic confidence model documented deterministic testable explainable — NOT statistical probability — documented as heuristic confidence score
- Semantic merge policy: when updating do not blindly replace unrelated metadata — existing role=button tags=["ui","interactive"] proposal tags=["primary"] update command must explicitly determine replace|merge|add|remove — MVP role->replace tags->replace relationships->replace with future granular — Documented
- Performance: deterministic correct bounded no infinite traversal no recursive cycles no uncontrolled graph expansion — guard against cycles relationships may form graphs but must not become SceneGraph hierarchy
- Security: no filesystem, no network, no arbitrary code execution, no external API calls, no hidden mutation, no dynamic code evaluation
