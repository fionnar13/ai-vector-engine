## 2. T06 Contract

- **Input schema (exact):** required `objectIds` (array), `transform` (object) (tools.js:328). Validator (:333): objectIds non-empty array; transform must carry ALL SIX numeric keys a,b,c,d,tx,ty ("transform must be Matrix3x3"); `det = a*d - b*c` with `|det| < 1e-12` → `TRANSFORM_SINGULAR`; objects must exist (:179-186).
- **What it writes:** geometry params ONLY, via `transformGeometryParams` (:86-111) through `writeGeometry` (:175-178; WC journaled modify or store update). Parametric-shape preserving per type: rect corners transformed then re-fitted to the axis-aligned bbox, rx/ry scaled by sqrt(|det|) (:90-96); ellipse center mapped, rx scaled by |(a,c)| column norm, ry by |(b,d)| (:97-100); line endpoints (:101); polygon points (:102); star center + radii by sqrt(|det|) (:103-106); text position only (:107); path anchors + handles (:108). Unsupported type → honest failure (:340, :109).
- **Resize width/height/area: YES.** Any scale component changes rect width/height (:90-96), ellipse rx/ry (:97-100), star radii (:105) — hence world area. (This is the lever the 3.16 constraint rule DECLINED to use for equalWidth/equalHeight because T06 is origin-anchored and MOVES objects — critic.js:466-471.)
- **Aspect ratio: YES.** Non-uniform scale (a≠d) changes rect aspect via the re-fit (:90-96) and ellipse rx/ry independently (:97-100); aspect_ratio evidence in T20 reads exactly these (:162-164 of semantic.js).
- **Position independent of size: YES, via matrix composition.** A pure translation (a=d=1, tx/ty) moves without resizing; a scale-about-a-point (translate·scale·translate composed into one matrix) resizes while holding a chosen point fixed. The tool applies the single matrix to LOCAL parametric coordinates (:86-88) — composition is the caller's obligation.
- **World vs local: T06 is LOCAL-ONLY.** Unlike T08/T09, which convert world deltas through `worldDeltaToLocal` (:162-171, used at :420, :477), T06 applies `input.transform` directly to local params (:339) — no world/local conversion inside the tool. Under nesting, the caller must pre-compose the parent world transform (ties to PHASE G #17).
- **Determinant/singularity guard: `|det| < 1e-12` → TRANSFORM_SINGULAR at VALIDATION time, before any transaction (:333).** The related world-delta path guards non-invertible PARENT transforms (T08 :421, T09 :478, T11 :546).
- Citations: tools.js:327-345, :86-111, :175-178, :333; transaction.js:529-538 (the latent no-op createTransformObjectCommand is NOT this tool's path — tools.js:330-332).

## 4. TransactionBuilder API

- **addCommand(cmd):** pushes the command, returns `this`; NO constraints checked at add time (:143).
- **build():** throws on ZERO commands ("Transaction must have at least one command", :145); `deterministic` = logical AND of every command's `deterministic` flag (:146); returns `createTransaction(...)` (:147).
- **Transaction record (:126-138):** `{id, parentId, commands (frozen), status:'pending', diff:null, inverse:null, deterministic, metadata (frozen {source, toolId, description}), createdAt: Date.now()}` — the record carries wall-clock createdAt (:136) and, by default, RNG ids (:128); the correction loop AVOIDS this entropy by passing explicit content-derived ids (`atx-` correction.js:2530, `ccmd-` :2421) while the plain tool wrapper does not (tools.js:217).

Any throw → status 'failed', rethrown, NOTHING committed (:225-228).
- **Commit-phase events, exact order (:441-449):** (1) `ObjectCreated` per added object (:442); (2) `ObjectUpdated` per modified object (:444); (3) `SceneGraphChanged` per modified node (:445); (4) `ObjectDeleted` per removed object (:447); (5) `TransactionCommitted` LAST, with diff counts (:448). - **Id generation:** uuid() RNG for transactions/commands/events by default (transaction.js:2, :128, :455…; EventBus :180); content-derived ids only where the caller supplies them (correction loop; deterministic idFactory :200 is RNG-backed uuid too).

## 5. Rollback API

- **Surface:** `TransactionExecutor.undo()` (:231-263) / `redo()` (:265-286); `HistoryManager` linear stack (:159-173); correction-layer wrapper `rollbackCorrectionAttempt` (correction.js:2675-2713).
- **Top-of-history constraint: YES — you CANNOT undo a non-top transaction.** `getTransactionToUndo()` returns ONLY the transaction at currentIndex (:167); undo() uses exactly that (:232-233). The correction loop HARD-ENFORCES ownership: `rollbackCorrectionAttempt` refuses with INVALID_ATTEMPT unless `getTransactionToUndo().id === attempt.transactionId` — "refusing to undo a foreign transaction (§32/§47)" (correction.js:2691-2694; header :2672-2674).
- **getInverse() contract:** per-command, zero-arg, returns an inverse command or null (:211-214). Null/missing getInverse on ANY command downgrades the WHOLE transaction to snapshot-inverse (:216-218). Among tool-backed correction commands, ONLY T05 declares an exact inverse (delta negation, correction.js:2452-2457; same idea in createMoveObjectCommand :525); createTransformObjectCommand has NO getInverse at all (transaction.js:529-538) — everything non-T05 rides the snapshot path.
- **Snapshot fallback:** before-snapshot over preloaded originals (:199, :388-395); `createInverseTransaction` → `createRestoreCommands` rebuilds delete/add/update commands from snapshot × original diff (:288-349, generic restore fallback :341-346); undo() loads affected entities of BOTH transactions and merges snapshot state (:237-248); the inverse commit publishes events and moves history back one (:258-260).
- **Redo** re-executes the ORIGINAL commands verbatim (:265-286) — re-derivation, not stored forward-diff.
- Citations: transaction.js:159-173, :211-218, :231-286, :288-349, :388-395; correction.js:2672-2713.
