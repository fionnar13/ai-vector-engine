## 3. Evaluation Engine (supported categories and tolerances)

`evaluate(expectedState, documentContext, evaluationContext)`
(`evaluation.js:980-1009`) — deterministic, contract-ordered:

- **E1 existence** (`evaluation.js:684-692`): every target must exist;
  existence failure short-circuits deeper checks for that target
  (`evaluation.js:996`).
- **E2 geometry** (`evaluation.js:695-732`): width/height/rx/ry/area/
  symmetric vs the canonical geometry record
  (`observedGeometryField`, `evaluation.js:660-677`; builder-exact area
  formulas `evaluation.js:669-672`).
- **E3 appearance** (`evaluation.js:738-802`): hex expectation vs the
  active solid fill; fill.enabled / fill.kind / fill.color / opacity paths;
  comparison in canonical RGBA space on both sides
  (`evaluation.js:766-778`).
- **E4 placement** (`evaluation.js:817-869`): centered (world-bbox center vs
  artboard center — the artboard is NEVER guessed:
  `evaluation.js:807-815, :988-989`) and expected-bbox modes.
- **E5 structure** (`evaluation.js:875-890`): directional grouped expectation
  vs the observed parent-is-group fact.
- **E6 semantic** (§20): dormant — no invented values; self-reported in
  `metadata.unevaluatedExpectations` (`evaluation.js:960-967`).
- **E7 transform** (`evaluation.js:896-952`): dormant while the expectation
  is null (§19 — no invented transform deviation); per-key comparison when
  set.
- **Tolerances** (§14): `EVALUATION_TOLERANCES` uniform 1e-9 — the
  geometry-kernel default (`evaluation.js:620-625`, `geometry.js:5/:338`);
  `withinTolerance` (`evaluation.js:652-654`); applied tolerances
  self-reported in `metadata.tolerances` (`evaluation.js:1005`).
- **Support pieces**: local hex→RGBA normalizer mirroring the substrate
  parser (`evaluation.js:635-650`); WorldBBox composed from public pure
  pieces only (`evaluation.js:155, :225-231, :286-298`); declared deviation
  order target-major then fixed category rank (`evaluation.js:969-975`);
  honesty self-report of unverifiable expectations
  (`evaluation.js:960-967, :1004-1007`).

## 4. Critic (rules and proposal model)

`proposeCorrections(evaluationResult)` (`src-js/critic.js:406-431`) —
validates its input through the evaluation module's own §12 validator
(`critic.js:104, :407-410`), then applies a fixed, capability-backed rule
table (header `critic.js:24-58`; dispatch `critic.js:389-395`):

- geometry → create-rebuild intent from the desired-state projection
  (`critic.js:300-328`);
- appearance fill/kind/color → T07 apply_fill
  (`critic.js:341-348`); opacity → T07 opacity-only
  (`critic.js:333-340`);
- placement.center → translate delta = expected − observed
  (`critic.js:352-364`); bbox edges propose nothing (§28 ambiguity,
  `critic.js:353`);
- transform.tx/ty → translate delta ONLY when the ExpectedState carries the
  non-null expectation (`critic.js:369-383`); matrix keys propose nothing;
- existence / structure / semantic → NO proposal (§28: the architecture is
  never bypassed, `critic.js:385-395`).

**Proposal model** (§25): `createCorrectionProposal` (`critic.js:240-267`)
builds a deep-frozen 7-key inert record `{id, deviationId, targetRef,
intent, reason, confidence, priority}` with content-derived id
(`critic.js:262-265`), intent frozen to the planning key vocabulary
(`INTENT_KEYS`, `critic.js:191-197`), `confidence` = rule-derived constant 1
(`critic.js:426`), `priority` = deviation index (`critic.js:427`). Dedup:
identical corrections for the same target collapse to the first deviation
(`critic.js:418-420`). `validateCorrectionProposal` (`critic.js:271-290`)
enforces the 7 keys, plain-data-only, and every §25 content contract. The
single orchestrator `evaluateAndCritique` (`critic.js:442-446`) composes
`evaluate` + `proposeCorrections` into a frozen `{evaluationResult,
proposals}` pair.
