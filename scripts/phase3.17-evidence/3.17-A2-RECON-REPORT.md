## 2. A5 — Confidence Model

1. **Formula**: `confidence = clamp01(baseConfidence + sumWeights*0.3)` (semantic.js:252-253; `clamp01` :120). Frozen counterpart: same formula, heuristics.ts:206 (comment "transparent model: base + 0.3*sumWeights").
2. **Range**: [0,1] — clamped (:120, :253); validated [0,1] at the store boundary (semantic.js:41-47). No-evidence floor 0.3 (:245); unknown cap ≤0.5 (:256).
3. **Semantics**: heuristic evidence-weighted score, NOT a probability. It is a transparent additive heuristic (comment "transparent model", frozen heuristics.ts:206); the proposal record carries no probabilistic contract; nothing downstream treats it as a probability. Spec §11:378-383 requires exactly this: "Confidence MUST remain informational. It MUST NOT automatically become: mutation permission, correction authorization, truth, canonical state, evaluation success."
4. **Threshold consumer**: **NONE.** No module compares T20's semantic confidence against a threshold. All confidence comparisons in src-js are (a) internal to the engine: no-evidence floor :245, unknown cap :256, demotion :258; (b) range validation: semantic.js:44-45, critic.js:227-228, constraint-inference.js:302-303; (c) correction §19 priority product over STRATEGY confidence (correction.js:1523) — the correction-domain confidence, not T20's. Spec §36:1048-1053 forbids inventing thresholds; none exists to reuse.
5. **No-evidence branch**: `confidence: 0.3` with `proposedRole:'unknown'` and one weight-0 evidence row `[{signal:'geometry_type', description:'insufficient evidence', weight:0}]` (semantic.js:238-250, specifically :245-:246).
6. **vs 3.16 T19**: T19 emits the CONSTANT `confidence: 1` (constraint-inference.js:240; "exact geometric fact within tolerance", tools.js:932; validation (0,1] constraint-inference.js:302-303). T20 emits a GRADED heuristic score in [0,1] with floor 0.3 and internal caps. Normalization design implication: T19 consumers could treat confidence as a constant sentinel; T20's must be carried verbatim as a graded value (spec §11 informational; §36 no thresholds; §05:180 "fabricate semantic confidence values" forbidden). A shared normalizer cannot assume one confidence regime — the two proposal classes differ materially.
