## 4. Design decisions BD-1..BD-7 (all pinned in module header + tests)

- **BD-1 vocabulary = T20 emission vocabulary, no mapping.** T20 emits exactly 7 roles
  (semantic.js:136/:149/:169/:174-208/:220/:242-259); VALID_ROLES has 14 (semantic.js:6);
  no aliases exist in src-js (A-2/A-4). Mapping would be invention (3.16 D-8 precedent).
  The other 7 VALID_ROLES members are refused `UNSUPPORTED_TYPE` — the boundary does not
  widen the vocabulary to the store set. **Recommendation confirmed.**
- **BD-2 `unknown` accepted (option a).** T20 honest-labels it (semantic.js:242/:255/:259,
  incl. no-evidence 0.3/confidence branch :239-249 — N-14 replicates that record
  verbatim and normalizes it). Refusal stays future-proof for never-emitted roles.
  **Recommendation confirmed.**
- **BD-3 confidence preserved verbatim (option a).** No rounding/clamp/threshold (§36
  forbids magic thresholds; A-5 proved no threshold consumer exists). Null arm for
  missing/non-numeric per the pinned record shape. **Recommendation confirmed.**
- **BD-4 provenance = `{source:'T20', evidence:[...]}`.** The tool is the origin;
  'heuristic' is the algorithm (semantic.js:247/:277). Evidence copied + frozen,
  content verbatim (N-7). Keeps §37's T20-inferred/user/derived distinction visible
  without a parallel provenance field. **Recommendation confirmed.**
- **BD-5 entropy stripped; content-derived id.** Upstream `proposalId` (RNG uuid,
  semantic.js:2/:240/:270) and `createdAt` (wall-clock, :248/:278) never appear in
  output (N-10). `id = 'smr-' + fnv1a32(stableStringify({objectId, role, confidence,
  evidence}), 0x811c9dc5)` — 8 lowercase hex (N-5 proves entropy- and key-order-
  independence, evidence-sensitivity). **Approach confirmed** with one precision note:
  the prompt pins a single-pass 8-hex scheme, different from 3.16's 4-pass
  deterministicUUID — followed the prompt (different artifact class; 32-bit collision
  domain disclosed in §8).
- **BD-6 refusal shape = `{status:'REJECTED', reason, upstream}`.** Pinning surfaced a
  precision finding: **constraint-inference.js itself produces no refusal records** —
  it throws `InferenceError` or returns `unmatched[]`; the real 3.16 refusal precedent
  is the correction-loop **refusalLedger** (`correction.js:1953`
  `{status:'PLAN_REFUSED', reason, details}`; ledger entries :3043). The session
  follows that family: flat, reason-carrying, frozen, **never throws** (BD-6's "when
  T20 fails... produces a refusal"). `upstream` is a verbatim **deep-frozen
  session-owned copy** — the first GREEN run exposed that the by-reference variant
  made `deepFreeze` walk into (and freeze) caller-owned data, violating the 3.16
  no-mutation discipline (constraint-inference.js:36-37 "nothing here aliases caller
  structures"). Copy semantics fixed and pinned (N-15). Shape matches 3.16 precedent:
  **confirmed, with the citation refined as above.**
- **BD-7 zero imports, local reimplementation.** `fnv1a32`/`stableStringify`/
  `deepFreeze` reimplemented locally mirroring constraint-inference.js:140-180 (3.16
  itself reimplemented rather than importing from correction.js). Static scan N-16:
  no static/dynamic imports, no require, no re-exports. **Confirmed.**

Session semantics pinned alongside: `ingest` accepts ONE T20 tool-result envelope
(single contract — a bare proposals array is `MALFORMED`, no guessing); per-proposal
isolation inside a valid envelope; cumulative frozen snapshots; registry snapshot
`{records, refusals}`.
